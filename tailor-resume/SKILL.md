# Tailor Resume

Read `references/priority-hierarchy.md`, `references/data-directory.md`, and `references/prerequisites.md`. A supplied resume and posting are sufficient; no separate setup or profile interview is required.

1. Use the posting URL/text or unambiguous target already supplied. For an explicitly requested `last` job, select the most recent saved posting and state the selected role. Ask only if the target is missing or ambiguous. Fetch URLs using `references/browser-setup.md`; use pasted posting text when supplied. Save provenance and parsed posting in its per-job folder.
2. Extract title/level, company, responsibilities, must-haves, preferred qualifications, and keywords. Map requirements to direct, adjacent, or transferable candidate evidence. Identify gaps without fabricating experience.
3. Read `scripts/tailor-resume.md` for writing guidance. Work locally; it is an instruction reference, not a required subagent. Reorder and reframe supported achievements for the target role. Preserve job titles, dates, attribution, and real scope. Use only supplied metrics; omit unverified business models, responsibilities, and results. Existing resume format and user requirements take precedence over template preferences.
4. Review each claim against its source and employer/date range. Check meaningful keyword alignment, concise bullets, appropriate seniority, and unsupported claims. Do not force readability or metric quotas at the cost of accurate technical language. A missing profile should result in conservative wording or a focused factual question, not invented assumptions awaiting approval.
5. Save `resume.md` in the matched job folder, preserving the original resume and prior materially different drafts. Present the draft with key changes, unresolved factual gaps, and an absolute file link. For requested PDF/DOCX output, use the available document skill and verify the rendered artifact.
6. Apply user corrections and record relevant confirmed facts in `DATA_DIR/profile.md` under the right employer and dates. `references/profile.md` is an optional scaffold; populate only confirmed information. Continue to cover-letter or application work if already requested.
